## 同机性能对照

环境：Apple M1 Pro、macOS arm64、Node v24.15.0，启用显式 GC。修复前代码来自 `git archive 12419de` 的独立临时目录，使用与修复后相同的微基准脚本和依赖；两次测量顺序执行。队列含 200 条事件，每条约 4 KiB Unicode 属性，属性长度符合单字段限制。下表耗时为预热后的样本中位数；每项 5 或 7 个样本。

| 场景 | 修复前 | 修复后 |
|---|---:|---:|
| 200 条事件入队 | 135.31 ms | 3.47 ms |
| 200 条事件分批领取 | 27.86 ms | 0.57 ms |
| 满队列下重复离线调度 200 次 | 183.04 ms | 1.38 ms |
| 百万码点属性归一化 10 次 | 143.01 ms | 0.29 ms |
| 100 项长属性数组归一化 3 次 | 1140.08 ms | 0.18 ms |
| 2000 个监听器的 SFC 插桩 | 123.89 ms | 46.56 ms |
| 慢存储期间 201 次队列持久化调用 | 201 次实际写入 | 2 次实际写入 |
| 同场景写入总量 | 186.55 MB | 1.86 MB |
| 同场景额外保留堆内存 | 140.64 MB | 1.15 MB |

原始结果位于仓库生成目录 `test-results/stress-before.json` 和 `test-results/stress-final.json`。MB 按十进制用于展示实测字节数，队列内部 2 MiB / 批次 512 KiB 限额仍按 1024 换算。少量样本的尾部延迟易受 GC 和系统负载影响，不将中位数改善解释为真机 SLA 或稳定吞吐承诺。

完整运行时场景：

- 10000 次在线 `track` 全部接纳；加上初始化、同意恢复和后台事件，共观察到 10005 条事件；队列、在途槽位和定时器最终均为空，最终序号与落盘记录一致。
- 20000 次离线提交中，198 条业务事件与已有 VISIT/PAGE 构成 200 条队列；其余 19802 次按容量契约返回拒绝。重连使用 4 个批次排空，最大并发 3，无额外重复接收或序号复用。
- 3 个固定种子，各 5000 次混合提交、断网、同步派发异常、超时、HTTP 400/503、重复回调及 force flush；每个接纳事件最终属于成功或预期丢弃之一，二者不重叠，结束时无遗留请求/定时器/刷新等待。
- 另有 5000 次队列入队、删除、重试、批次领取和快照恢复交错，逐步检查完整信封字节数、条数、唯一请求标识和批次限制。

1. 初审建立基线：类型检查和 658 项现有测试通过；微基准复现内存与 CPU 开销。首次沙箱运行的 4 项 HTTP 测试因监听端口被禁止而失败，允许本地监听后全部通过。

3. 第二轮修复及复审：统一每键写入边界、限制长数组拼接、优化模板替换；大流量和故障交错验证继续暴露观察回调的重试内容污染，随后修复。
4. 最终复审第一轮：重读全部变更，复核字节记账、快照隔离、写入失败恢复、并发与迟到回调；定向测试、压力场景及固定种子交错均通过，没有新增可复现问题。

提交前再次审阅全部未提交改动，收紧两项测试边界：压测读取最终存储时必须实际存在队列和序号键，缺失不能按空记录通过；故障交错测试逐类核对网络、400/503、超时、同步派发异常、断网和强制刷新确实发生，并确认达到三个并发槽位。代码按队列/持久化修复、属性/编译性能优化、压力验证与文档三个边界组织提交。

## 结论与验证边界

本轮发现的问题均已修复，最终连续两轮复审未发现新增可复现问题。该结论限定于已审阅源码及可重复的自动化场景，不表示对所有运行环境不存在缺陷的数学保证。
